# DeepSeek 专用配置设计

## 目标

将现有的通用 OpenAI 兼容配置改为 DeepSeek 专用体验。用户只需输入 DeepSeek API 密钥；API 地址固定为 DeepSeek 官方端点，模型在聊天页面随时切换。

## 用户体验

- 设置页删除 API 地址和模型名称输入框，只显示“DeepSeek API 密钥”。
- 密钥默认仅保存在当前浏览器会话中，关闭标签页后清除；不发送到 DeepSeek 以外的服务。
- 聊天页提供紧凑的模型切换器：
  - `V4 Flash` 对应 `deepseek-v4-flash`，为默认模型。
  - `V4 Pro` 对应 `deepseek-v4-pro`。
- 用户可以在对话过程中切换模型，已有消息不清空；切换后的下一条消息使用新模型。
- Next.js 开发工具栏保持原样，不属于网站 UI，也不纳入本次改动。

## 架构与数据流

1. 浏览器仅保存 API 密钥和当前模型选择。
2. 聊天请求向站内 `/api/chat` 发送密钥、模型和消息；不再接受客户端提供的 API 地址。
3. 服务端固定请求 `https://api.deepseek.com/chat/completions`。
4. 服务端使用模型白名单，只接受 `deepseek-v4-flash` 与 `deepseek-v4-pro`，拒绝其他值。
5. 设置页的连接测试固定使用 `deepseek-v4-flash`，成功后保存密钥。

## 错误处理

- 未配置密钥：提示先前往设置页填写 DeepSeek API 密钥。
- 密钥无效或权限不足：显示认证失败提示。
- 余额不足、请求限流、上游暂时不可用：根据 DeepSeek 返回状态显示对应中文提示。
- 非白名单模型：由服务端拒绝，不向上游发送请求。
- 网络异常：显示可重试的中文错误，不泄露密钥或上游响应中的敏感信息。

## 安全与隐私

- DeepSeek 域名在服务端固定，不再依赖可变的出站域名允许列表。
- API 密钥只通过请求体传入站内路由，再作为 Bearer Token 发往 DeepSeek。
- 日志和错误信息不得包含完整密钥。
- 默认使用 `sessionStorage`；本次不增加长期保存选项。

## 测试与验收

- 单元测试：配置结构只接受密钥；默认模型为 Flash；模型白名单拒绝其他值。
- 路由测试：目标地址固定为 DeepSeek；两个 V4 模型均可请求；上游错误映射为中文提示。
- 组件测试：设置页仅有密钥输入；聊天页可切换模型且不清空消息。
- 浏览器验收：录入密钥、测试连接、进入聊天、切换 Flash/Pro，并验证下一条消息使用所选模型。
- 全量运行 lint、测试与生产构建。

## 不在范围内

- 翻译或隐藏 Next.js 开发工具栏。
- 支持其他模型供应商或自定义 API 地址。
- 将用户密钥保存到服务端数据库。
