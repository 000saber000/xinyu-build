# 心屿：人机交互心灵驿站设计规格

日期：2026-06-20  
状态：已完成产品与视觉方向确认，等待用户复核书面规格

## 1. 产品定位

“心屿”是一个面向普通成年用户的网页心灵驿站。它通过沉浸式治愈庭院，把 AI 陪伴对话、情绪记录和短时放松小游戏组织成一次自然的“漫游”，而不是传统工具型仪表盘。

产品提供情绪陪伴和自我整理体验，不提供医学诊断，不替代心理咨询、医疗服务或紧急援助。

## 2. 首版目标与范围

首版必须完成：

- 半写实动态庭院首页及可交互场景热点。
- 用户自备 API 配置，兼容 OpenAI 风格接口。
- 流式 AI 对话和五种预设陪伴者。
- 心情签到、私人日记和基础情绪趋势。
- 呼吸花开、心绪溪流、花房养成三个轻量小游戏。
- 本地优先的数据保存、导出和清空。
- 桌面端与移动端适配、减少动态效果模式及键盘可访问性。
- 危机表达识别与现实求助提示。

首版不包含：

- 用户账号、云同步、社交社区或公开内容。
- 付费系统、广告、排行榜、连续签到惩罚或强制留存机制。
- 完整 3D 自由漫游和高成本角色捏脸。
- 医疗诊断、治疗方案或冒充真人心理医生的角色设定。

## 3. 视觉方向

已确认方向为“雾光花园”：半写实晨光庭院、温暖自然的成年化审美，以及克制的玻璃拟态界面。

### 3.1 色彩与材质

- 暖象牙白 `#F6F1E7`
- 鼠尾草绿 `#8EA58C`
- 雾紫 `#B9AFCE`
- 苔藓绿 `#566B57`
- 淡日光金 `#E8C98D`

场景包含暖色石径、植物、薰衣草色花卉、浅溪、薄雾、晨光、倾听小屋和玻璃花房。界面使用半透明磨砂卡片，但文字与背景必须保持可读对比度。

### 3.2 动效

允许的环境动效包括薄雾漂移、树叶轻摆、水面涟漪、柔光呼吸和热点光晕。动效应缓慢、低刺激，不使用闪烁、突发缩放或高频视差。

系统尊重 `prefers-reduced-motion`，并在站内设置中提供“减少动态效果”开关。开启后保留静态层次和必要状态反馈，停止装饰性循环动画。

### 3.3 响应式表现

桌面端使用全景庭院作为主视觉。移动端不缩放整张桌面场景，而改为纵向漫游路径，按倾听小屋、心绪溪流、静心花房的顺序组织内容。

正文字号不低于 16px。所有主要入口、弹窗和游戏控制均支持键盘操作，并显示清晰的焦点状态。

## 4. 信息架构

### 4.1 庭院首页

首页负责建立情绪氛围和分发入口，包含：

- 顶部导航：心屿、漫游、心情日记、小游戏、个人设置。
- 中央引导语：“今天，想去哪里走走？”
- 倾听小屋、心绪溪流、静心花房三个场景热点。
- 左下角心情签到卡片：“此刻的你，感觉如何？”
- 右下角“我的陪伴者”选择器。

### 4.2 倾听小屋

倾听小屋承载 AI 对话：

- 新建、继续、删除本地会话。
- 流式显示模型回复。
- 切换陪伴者、回应长度和表达风格。
- 保存完整对话，或仅将用户选中的内容写入日记。
- 显示模型连接状态、停止生成、继续和重试操作。

### 4.3 心绪溪流

用户写下一段情绪或烦恼，文字变成叶片随水漂走。提交前可选择：

- 仅完成释放动画并立即销毁文本。
- 将原文保存到私人日记。
- 将简短情绪标签保存到当天心情记录，不保存原文。

系统不得在用户选择销毁后保留可恢复副本。

### 4.4 静心花房

花房包含三个 1–5 分钟的轻量体验：

1. **呼吸花开**：光圈引导吸气、停留和呼气，完成后花朵绽放。用户可随时退出，不把未完成视为失败。
2. **心绪溪流**：从花房游戏列表进入同名情绪释放体验，与庭院热点共享同一功能模块。
3. **花房养成**：心情签到、日记或完成练习可获得“晨露”，用于培育植物。晨露只用于轻量反馈，不出售、不排名、不因断签扣除。

### 4.5 心情日记

日记包含日历视图、每日心情、用户正文、用户主动保存的对话片段，以及基础趋势图。趋势只陈述记录变化，不推断疾病或给出诊断。

用户可按条目导出或删除，也可导出全部数据和一键清空本地数据。删除日记和全量清空均需要二次确认。

### 4.6 设置中心

设置中心包含：

- API 地址、API 密钥、模型名称。
- 连接测试和可理解的错误反馈。
- 陪伴者、回应长度、说话风格。
- 动效、声音、主题和隐私设置。
- 数据导出与清空。

密钥输入默认隐藏，不进入日志、分析事件或错误报告。

## 5. 陪伴者设计

首版提供五种预设陪伴者：温柔姐姐、沉稳青年、金毛、猫咪和幻想精灵。用户可配置称呼、说话风格和回应长度，也可上传本地头像作为自定义外观。

陪伴者只改变措辞、节奏和界面形象，不能改变安全边界，不能声称是真人、心理医生或具有临床资质。角色提示词由“稳定安全规则”和“可选表达风格”分层组成；表达风格不得覆盖安全规则。

## 6. 技术架构

### 6.1 前端

- Next.js 与 TypeScript 构建页面和服务端路由。
- 庭院使用分层图片、CSS 动效与必要的 Canvas 效果实现，不采用完整 WebGL 自由漫游。
- 业务按庭院、聊天、日记、小游戏、设置、安全检测拆分成边界明确的模块。
- 每个小游戏拥有独立状态机和存储接口，可单独测试和替换。

### 6.2 模型适配层

模型层首先支持 OpenAI 风格的流式聊天接口。统一适配接口接收 API 地址、密钥、模型名、消息和取消信号，并输出标准化的增量文本、完成状态和错误类型。

界面不得直接依赖某个模型供应商的响应结构。未来增加其他供应商时，只新增适配器，不修改聊天页面和陪伴者逻辑。

### 6.3 无状态代理

浏览器将当次 API 配置与聊天请求发送到本站无状态代理。代理完成目标地址校验、请求转发、超时控制和流式响应，不把密钥、提示词或对话写入数据库及应用日志。

代理只允许 HTTPS 目标，并阻止本机地址、私有网段、云元数据地址和重定向到上述地址，避免配置式服务端请求伪造。部署环境可提供允许域名列表；自定义供应商需要显式加入配置。

### 6.4 本地存储

日记、心情、聊天、游戏进度和偏好使用 IndexedDB。API 配置存于当前浏览器；密钥不得以明文出现在 URL、日志或导出文件中。浏览器端无法提供与服务端密钥库等价的保护，因此界面必须明确提示：共享设备不建议保存密钥，并提供“仅本次会话使用”。

首版不实现账号与云同步。

## 7. 数据流

### 7.1 AI 对话

1. 用户输入内容。
2. 客户端先将草稿保存在内存，发起请求后再写入本地会话。
3. 安全层检查用户输入；紧急风险命中时优先进入危机响应流程。
4. 模型适配层通过无状态代理发起流式请求。
5. 客户端逐段渲染回复，并在正常结束后保存完整消息。
6. 中断时保留已收到内容和用户原文，提供继续或重试。

### 7.2 心情与日记

心情签到写入日期、情绪类型和可选备注。溪流和聊天内容只有在用户主动选择时才进入日记。趋势图仅读取结构化心情记录，不读取或分析日记正文。

### 7.3 游戏进度

小游戏只保存完成时间、可选练习偏好、植物状态和晨露数量，不保存呼吸过程中的细粒度行为数据。

## 8. 错误处理

模型错误被归一化为：配置缺失、认证失败、模型不存在、余额或配额不足、请求过频、网络中断、超时、供应商异常和响应格式不兼容。

每种错误提供：发生了什么、用户可采取的下一步，以及不丢失当前输入的重试操作。错误信息不回显完整密钥，不直接展示可能包含敏感内容的原始供应商响应。

IndexedDB 不可用或空间不足时，界面切换为临时会话模式并明确提示内容不会持久保存。导入数据先验证版本和结构，再写入本地数据库；无效数据不得覆盖现有内容。

## 9. 安全与危机响应

危机表达使用本地高置信规则和模型辅助判断两层机制。高置信规则命中时不得等待远端模型才显示帮助信息。

危机界面应：

- 使用直接、尊重且不评判的语言。
- 鼓励用户立即联系当地紧急服务、危机热线或身边可信任的人。
- 根据部署地区提供可配置的本地求助信息；无法确定地区时使用通用指引，不编造号码。
- 保留“继续说说”入口，但不以普通陪聊取代现实求助。
- 不进行风险评分展示、疾病诊断或强制承诺。

首页、聊天页和设置页均清晰注明服务边界。

## 10. 隐私原则

- 默认本地保存，默认不建立账号。
- 只有实现功能所必需的数据才被处理。
- 用户明确决定哪些对话或溪流内容进入日记。
- 不接入记录对话正文的第三方分析服务。
- 数据导出不包含 API 密钥。
- 清空操作完成后，应用重新读取存储验证数据确已删除。

## 11. 测试与验收

### 11.1 自动测试

- 模型适配层：正常流式、取消、中断、异常响应和错误归一化。
- 安全代理：HTTPS 校验、私有地址阻止、重定向校验、超时和日志脱敏。
- 本地存储：创建、迁移、导入、导出、单项删除和全量清空。
- 聊天状态：发送、停止、重试、继续和历史恢复。
- 游戏逻辑：呼吸阶段、溪流保存选择、晨露与植物状态。
- 安全规则：高置信危机表达优先切换，以及普通负面情绪不过度触发。

### 11.2 浏览器验收

- 桌面和常见手机宽度下完成庭院到三个核心空间的全流程。
- 键盘可访问全部主要操作，焦点顺序合理。
- 系统及站内减少动效设置生效。
- API 密钥不会出现在 URL、控制台、应用日志和导出文件中。
- 网络中断时用户输入与已收到回复不会消失。
- 日记删除和全量清空符合确认与删除语义。

### 11.3 视觉验收

以用户确认的 UI 概念稿为基准，验收晨光庭院氛围、色彩、玻璃层级、热点可发现性、中文可读性、移动端改编和动画流畅度。视觉资源可以为性能做压缩，但不得退化成普通卡片式后台首页。

## 12. 完成标准

当以下条件全部满足时，首版才算完成：

- 六个主要页面或空间均可用，且能从庭院自然到达。
- 用户可配置并验证兼容接口，完成一轮可取消、可重试的流式对话。
- 五种预设陪伴者可切换，自定义头像可用。
- 三个小游戏均有完整开始、进行、结束和退出路径。
- 心情、日记、聊天和进度能够本地保存、导出和清空。
- 危机响应、服务边界和本地求助信息配置生效。
- 自动测试及桌面、移动端浏览器验收通过。
- 最终视觉与已确认的“雾光花园”方向一致。
